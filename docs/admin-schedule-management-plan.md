# 관리자 예약 일정 설정 기능 개발 계획

## 목적
원데이 수업 상세페이지의 `예약 가능 일정`을 하드코딩 목업이 아니라, 관리자가 직접 열고 닫을 수 있는 구조로 바꾼다.

## 사용자가 보는 화면
- 예약 가능 일정 달력
- 날짜별 표시 정보
  - 예약 가능 인원
  - 대기 인원
- 날짜 클릭 시 예약 신청 화면으로 이동
- 일반 달력 앱처럼 `<`, `오늘`, `>` 버튼으로 월 이동 가능
- 오늘 날짜는 달력 안에서 빨간 원형 표시

## 관리자가 설정해야 하는 항목
- 일정 생성
  - 수업 날짜
  - 시작 시간 / 종료 시간
  - 장소
  - 정원
  - 공개 여부
- 달력 공개/비공개
  - 공개: 사용자 달력에 노출
  - 비공개: 사용자 달력에서 숨김
- 예약 가능 인원
  - 정원 - 결제 확정 인원 기준으로 자동 계산
- 대기 인원
  - 해당 날짜 신청자 수 기준으로 자동 계산
- 상태값
  - 예약 가능
  - 대기 가능
  - 마감
  - 숨김

## 1차 구현
정적 GitHub Pages를 유지하면서 최소 관리 기능부터 만든다.

1. `data/classes.json` 생성
   - 공개 일정 데이터를 JSON으로 분리
   - index.html은 JSON을 읽어 달력을 렌더링
2. 관리자용 `admin.html` 추가
   - 일정 추가/수정/삭제 폼
   - 브라우저 localStorage에 임시 저장
   - JSON 내보내기 버튼 제공
3. 운영 방식
   - 관리자가 admin.html에서 일정 수정
   - JSON을 내려받아 `data/classes.json`에 반영
   - 커밋/푸시하면 공개 페이지 반영

## 2차 구현
수동 JSON 반영을 없앤다.

1. GitHub 저장소 API 또는 별도 DB 연결
2. admin.html 로그인 보호
3. 일정 저장 시 자동으로 `data/classes.json` 업데이트
4. 예약 신청 데이터와 연결해 대기 인원 자동 계산

## 3차 구현
예약/결제 흐름까지 연결한다.

1. 예약 신청 폼 저장
2. 결제 안내 대상자 선별
3. 문자 발송 대상 리스트 생성
4. 결제 완료자 반영
5. 여석 발생 시 다음 대기자 안내


## 4차 구현 — Solapi 문자 자동 예약
예약/결제/수업 전후 안내 문자를 Solapi로 자동 예약 발송한다. 공개 상세페이지에는 Solapi 명칭을 노출하지 않고, 관리자 기능 내부에서만 사용한다.

### 문자 자동 예약 트리거
1. 예약 신청 완료 문자
   - 발송 시점: 사용자가 예약 신청을 제출한 즉시
   - 대상: 신청자 본인
   - 목적: 신청 접수 확인, 결제 확정 전이라는 점 안내
   - 예시 문구:
     - `[근력학교] 케틀벨 원데이 수업 예약 신청이 접수되었습니다. 결제 안내를 받으신 뒤 결제까지 완료되어야 자리가 확정됩니다.`

2. 결제 안내 문자
   - 발송 시점: 해당 일정의 결제 안내 대상자로 선정됐을 때
   - 대상: 예약 가능 인원 안에 들어온 신청자
   - 목적: 결제 링크 전달, 결제 마감 시간 안내
   - 예시 문구:
     - `[근력학교] 케틀벨 원데이 수업 결제 순서가 되었습니다. 아래 링크에서 결제를 완료해주세요. 결제 완료 시 자리가 확정됩니다. 결제 링크: {payment_url}`

3. 여석 안내 문자
   - 발송 시점: 취소/미결제로 자리가 생기고 다음 대기자가 선정됐을 때
   - 대상: 다음 대기자
   - 목적: 여석 발생 안내, 결제 유도
   - 예시 문구:
     - `[근력학교] 신청하신 케틀벨 원데이 수업에 여석이 생겼습니다. 아래 링크에서 결제하시면 자리가 확정됩니다. 결제 링크: {payment_url}`

4. 결제 완료 문자
   - 발송 시점: 결제 완료 확인 직후
   - 대상: 결제 완료자
   - 목적: 자리 확정, 수업 기본 정보 전달
   - 예시 문구:
     - `[근력학교] 케틀벨 원데이 수업 예약이 확정되었습니다. 일정: {class_date} / 장소: 근력학교 고대점 / 준비물: 편한 복장, 물`

5. 수업 전 리마인드 문자
   - 발송 시점: 수업 1일 전 오후 6시, 수업 당일 오전 9시
   - 대상: 결제 완료자
   - 목적: 노쇼 방지, 장소/준비물 재안내
   - 예시 문구:
     - `[근력학교] 내일 케틀벨 원데이 수업이 진행됩니다. 일정: {class_date} / 장소: 근력학교 고대점 / 준비물: 편한 복장, 물`

6. 수업 후 복습 자료 문자
   - 발송 시점: 수업 종료 1시간 후
   - 대상: 출석자 또는 결제 완료자
   - 목적: 복습 교재 링크 전달
   - 예시 문구:
     - `[근력학교] 오늘 수업 고생하셨습니다. 복습용 교재 링크를 보내드립니다. 링크: {notion_url}`

7. 복습 영상 안내 문자
   - 발송 시점: 영상 링크 준비 후 관리자가 승인했을 때
   - 대상: 출석자
   - 목적: 비공개 복습 영상 전달
   - 예시 문구:
     - `[근력학교] 케틀벨 원데이 수업 복습 영상 링크입니다. 집에서 다시 확인해보세요. 링크: {video_url}`

### 관리자 화면에 필요한 기능
- 문자 템플릿 관리
- 발송 대상 미리보기
- 발송 예약 시간 설정
- 자동 발송/수동 승인 선택
- 발송 성공/실패 로그
- 실패 문자 재발송
- 수신 거부/오입력 번호 제외

### 상태 연동
- 신청 완료 → 예약 신청 완료 문자
- 결제 안내 대상 선정 → 결제 안내 문자
- 결제 완료 → 결제 완료 문자 + 리마인드 예약 생성
- 수업 종료 → 복습 자료 문자 예약 생성
- 영상 링크 등록 → 복습 영상 안내 문자 발송 대기

## 추천 순서
- 지금은 1차 구현부터 진행
- 이유: 현재 페이지가 GitHub Pages 정적 구조라서, 서버 없이 가장 빨리 관리 가능 구조를 만들 수 있음
- 이후 실제 신청 데이터가 쌓이면 2차에서 DB/로그인/자동 계산으로 확장
